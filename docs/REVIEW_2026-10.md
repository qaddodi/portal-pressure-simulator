# Review of the preview branch, October 2026: recommendations and plan

Reviewed: the integration branch `claude/settings-topbar-icon-flvft1` at commit `a04d37ad`
("Ascites: no pool while the Ascites test reads None"), the branch `/preview/` is built from.
Line numbers below refer to that commit.

How it was reviewed:

- The whole of `src/`, `styles/`, `tests/`, `scripts/`, the workflows and the docs were read, split
  across four focused passes (performance, graphics, interface and decks, code quality).
- The app was run in Chromium with Playwright: screenshots on desktop (1440×900) and phone
  (390×844, 2×) of Anatomy, Circuit, Lobule, Home, five deck slides and three patients; the repo's own
  `npm run perf`; and a CPU sampling profile of the running figure on the desktop and phone profiles.
- `npm run lint` (0 errors, 7 warnings) and `npm test` (518 pass; 1 m 45 s cold, 72 s of it the
  deck-threshold cache that CI never restores).

One caveat on the measurements: the cloud container has no GPU, so the vessels ran on the software
renderer (`data-renderer="software"`, 8 fps by design). Frame rates measured here say nothing about
real devices. The CPU profile is still useful: it shows where the main thread's own JavaScript time
goes, and those costs exist on every device.

Nothing in the repository was changed by this review except adding this file.

### Ranked recommendations

**P1. Stop the profile chart's endless glide (S).** `src/ui/charts.js:68-89`: the easer tracks the
beat-filtered pressure, which never settles below the 0.02 mmHg threshold (`src/ui/util.js:515`), so
`draw()` clears and repaints the whole chart on every display frame while the Tests dock is open
(it opens with the profile pane by default, `src/ui/dock.js:327`), and reads `cv.offsetParent` each
frame. Change: settle when no station moved ≥ 0.25 px on screen (compare `y(v)`, not mmHg) or
quantise the target as the stage does (`qP`, `stage.js:956`); pace the glide to 30 Hz; use the
IntersectionObserver visibility pattern already in `src/ui/pressure-time.js:237-241`. Verify with
`window.pps.perf().totals.ms.charts`.

**P2. Measure the home framing only when something that moves it changes (S).** `defaultVT`
(`stage.js:1331-1360`) and `followHome` (`:2088-2100`). The box only changes when the spleen's
size step, the ascites volume step, the caudate lobe, or organ visibility changes; all of those are
already keyed (`updateOrgans` keys at `:3800-3820`, ascites at `:3840`). Set a `homeDirty` flag from
those key changes and from `resize`/`pps:occ`, and have `followHome` return early otherwise. Same for
`readBlockers` (`:5321`): keep the 100 ms cadence but skip the `getComputedStyle` call when the
element's class list has not changed since the last read, and cache the node list until a card
opens or closes (`pps:occ` already fires then).

**P3. Pressure-over-time trace: scan the window once per draw (S–M).** `src/ui/pressure-time.js:180-183`
rescans ~6 k samples linearly for each of ~5 traces up to three times per draw, at the display
rate, allocating fresh arrays. `fine.t` is sorted: binary-search the window start once per draw,
memoise per-key series within a draw, and pace to 30 Hz (or scroll only the new strip as
`src/ui/doppler.js:776-780` does).

**P4. Layout reads inside per-frame loops (S).** `src/ui/dock.js:465` (`workspace.offsetParent` on every
painted model frame, right after the stage's SVG writes), `src/ui/fibroscan.js:191, 201`,
`src/ui/lobule-zoom.js:1558, 1567` (`getBoundingClientRect` + `getComputedStyle` per drawn frame),
`src/ui/sinusoid-view.js:599, 617`. Reuse the two existing patterns: IntersectionObserver for
visibility, a ResizeObserver-cached host rect (as `stage.js:1168-1176`), and a computed-style cache
keyed on theme.

**P5. Corner credit: cheap signature before measuring (M).** `src/ui/credit.js:323-360, 445-452`: a 1 s
poll plus every `transitionend`/`animationend` in the document (label opacity transitions fire these
constantly) runs `check()`, which reads `getScreenCTM`, the wrap rect, every obstacle rect and two
rects per label before computing the signature. Compute the signature first (CTM string, label count,
obstacle classes, wrap size) and return when unchanged; better, take label boxes from the stage's own
solved layout through a small stage API instead of DOM rects.

**P6. `syncVeins` rebuilds everything per frame while any glow eases (M).** `stage.js:1079-1080`
and `:6727` set `glowSync` each frame; `animate` then runs `glItems()` (~300 objects), refills
`tubeData`, compares it element-wise and `JSON.stringify`s the look (`:2843-2863`). Hover (0.28 s),
slide focus (0.5 s), Doppler (0.36 s) and selection (0.45 s) glows therefore double the figure's cost
exactly while the user interacts. Write only the glow texels of the affected rows (offset
`o + 40..48`, `:2840`) and add those rows to the existing `drawRows` path.

**P7. Per-frame allocations in `composite()` (S).** `src/ui/veins-gl.js:1618-1670`: six `new Float32Array`
per frame (`:1622, 1626, 1647, 1653, 1658, 1662`), three `.slice()`s, ~50 uniform uploads, and the
caller builds a fresh `bloodLook()` object including `bleedSpray()` every frame (`stage.js:6616`).
Preallocate, and key the slow-changing uniforms so only `clock` and the inverse matrix go every frame.

**P8. Comparison header rebuilt every painted frame (S).** `src/ui/dock.js:694-701`
`replaceChildren` at 10 Hz while a comparison is pinned; `src/ui/compare.js:54-57` already shows the
signature pattern.

**P9. FibroScan ripples rewrite SVG `d` every frame (M).** `stage.js:4243-4271`, under a group with
`filter: blur(5px)` (`styles/app.css:2765`). Animate `transform: scale()` and opacity on fixed paths
(compositor only) or draw them in the GL line layer as the organ outlines are (`olStep`, `:3314`).

**P10. Worker cannot keep up at 4×–8× (M).** `src/worker-core.js:127-137`: at 8× with the pulse on it is
200 steps of 4 ms per 33 ms tick, ~24 ms on a desktop CPU (measured 119 µs per step in Node), so
frames arrive late on phones. Use `h = 0.008` at speed ≥ 4 or cap `n` and stretch the clock
explicitly. This changes the timestep only at high speed and must pass the acceptance suite; note
`docs/PERFORMANCE.md` currently promises the timestep is untouched.

**P11. Lobule idle preparation and teardown (S).** The field tiles are prepared while Anatomy is shown
(`fibrousBand`, `drawTile`), and `release()` (`lobule-zoom.js:627-633`) zeroes four canvases, which
the profile shows as 293 ms of native canvas work on the desktop. Prepare in `requestIdleCallback`
slices of ≤ 8 ms with a deadline check, and release the canvases one per idle slice rather than all
at once on the way out.

**P12. Smaller items (S each).** Skip `setA` writes to SVG tubes hidden under `.gl-on`
(`stage.js:2200-2230`, `app.css:121`); memoise `labelSig` parts on the `params` object identity
(`stage.js:5442-5463`); key `textW`'s cache on the digit-normalised text (`stage.js:4929`); fonts and
`brand/` stale-while-revalidate in the source `sw.js:31-36` (the production SW from `scripts/build.mjs`
is already cache-first).

Already fine (checked, no change recommended): the engine's per-step cost and frame payload; the single
frame scheduler with sleep; the attribute cache, colour quantisation and width hysteresis on the model
frame; partial row redraw of the vessel layer; hit testing on `.v-hit` only; lobule, sinusoid and
endoscopy keyed redraws; Doppler strip scrolling; memory trimming of traces; the FLIP top bar; code
splitting and idle warm-up of the palette and presenter.

## 3. Quality

### Correctness defects (fix first)

**Q1. Silent engine death.** `src/worker-core.js:184` `setInterval(tick, 33)` has no try/catch, and
`src/ui/host.js:29` sets `onerror` only to reject the start-up promise. A `Singular matrix` throw
(`src/engine/linalg.js:10`) or a NaN after an extreme setting stops frames with no toast; the figure
simply freezes mid-lecture. Wrap `tick` (stop, post `{type:'error'}`, restore the last snapshot), make
the runtime `onerror` toast and reject pending commands, and add a finite check after `solve`. Add a
unit test with a singular topology. The toast should read as a learner sentence ("The model stopped.
Reload, or restart this patient") with a Reload button; `toast()` already supports one (`src/ui/util.js:98`).

**Q2. Share links.** `src/engine/scenario.js:128-137` `deepMerge` writes any key, so a crafted `#s=`
payload can set `__proto__`; `src/ui/main.js:379-391` applies `view`, `sel`, `cam` and `preset` without
validation (NaN camera, unknown view). Skip `__proto__`/`constructor`/`prototype`, use `Object.hasOwn`,
validate against the known sets and `Number.isFinite`; extend `tests/sanitize.test.js`.

**Q3. Popover listener race.** `src/ui/util.js:236` registers the outside-click and Escape listeners in a
`setTimeout(…, 0)` that `closePopover`'s cleanup cannot cancel, so open-then-close within one task
leaks listeners that close the next popover on its first pointerdown. Keep the timer id and clear it.

**Q4. Unknown `?preset=` opens the nearest match silently (`main.js:263-266`).** A syllabus typo opens
the wrong patient in a lecture. Toast and open the Patients tab with the search prefilled instead.

**Q6. One worker bootstrap.** `src/ui/host.js:20-44` and `src/ui/presenter.js:1062-1085` both start a
module worker, wait 15 s and fall back to `worker-core`; only the presenter's copy handles a runtime
error. Export `createEngineHost()` from `host.js`.

**Q7. De-duplicate helpers.** `clamp` ×6 (`util.js:383`, `trace-room.js:6`, `sinusoid-model.js:5`,
`card-place.js:5`, `clot-shape.js:6`, `physiology.js:3`), seeded RNG ×3, easings ×3 with different
curves (`stage.js:2004` quadratic vs `worker-core.js:52` and `presenter.js:46` cubic), the share codec
×2 (`main.js:369-378`, `presenter.js:39-40`), the mL/s→L/min factor `0.06` written ten times across
`metrics.js`, `explain.js` and `engine.js`. Add `src/math.js`, `src/engine/units.js`, `src/ui/share-codec.js`.

**Q8. Settle promises instead of guessed delays.** 33 `setTimeout`s in `stage.js`, 26 in
`presenter.js`, including a 40-try retry loop (`stage.js:1774`), `setTimeout(showFigure, 4000)`
(`:2029`), repeated `lookHome` at 500/1300 ms (`:2104`) and `go` fired twice (`presenter.js:925`).
A `whenSettled(el)` on `transitionend` with a timeout fallback, one `figureReady` promise, and

the matching sleeps in the e2e tests.

**Q9. Injectable singletons.** `store.js`, `host.js`, `frame.js` and `fibroscan.js:45` (`REDUCED`
evaluated once at import) are module singletons; factories with default instances make a fresh store
or host per unit test possible.

### Engine

**Q10. Solver tests at the dt values the app really uses.** T18 stability runs only at dt 0.02 with
single-parameter extremes; the app steps at 0.004 / 0.02 / 0.1 / 0.5 / 5 s (`worker-core.js:135`,
`engine.js:621, 628`). Add a `linalg.js` unit test (random SPD vs reference, singular detection), T18
variants at 0.004 / 0.5 / 5 with paired extremes, and a preset × action sweep asserting no throw.

**Q11. Determinism of the slow clock.** T17 covers `step` only, while the deck-state cache assumes
`advanceDays`/`sequence` are deterministic.

**Q12. Diode chatter at reversal.** `engine.js:426-431` picks the diode conductance from the previous
step's gradient; iterate once on a flip (cap 3) or smooth the conductance, and assert no flow chatter
in T18.

## 4. Graphics

The organ art is path data in `src/ui/anatomy.js` (`ORGANS` 411–436, `ORGAN_DETAIL` 437–447), assembled
into SVG in `src/ui/stage.js` (defs 424–444, 548–551; organ groups 560–603; liver pathology 604–765)
and rasterised once per state to a GPU plate (`stage.js:3000-3098`) that the vessel compositor draws
under the tubes (`src/ui/veins-gl.js:965-975`). Because the plate is drawn once per state, none of the
organ recommendations below add per-frame cost.

What the screenshots show today: the GPU vessels are the strongest element (analytic anti-aliasing,
filleted joins, per-tier casing, contact shadow); the deck slides are excellent; the lobule and
sinusoid views are rich. The organs are the weak spot: flat tinted silhouettes with one shared
highlight position, a cirrhotic liver that reads as a fine dot pattern at the same size as a healthy
one, a spleen that scales about its centre, a flat straw band for ascites, no pancreas, and in dark
mode organs that merge into one brown mass behind beautiful vessels. Blood is physically the best part
of the app and visually the least legible at projector distance.

### Organs

**G1. A cirrhotic liver that looks cirrhotic (M).** `stage.js:722-765` (`morphLiver`; contour push at
`:747` is ±2.2 units on a ~540-unit organ), `:709-713` (`liverField`), `:3800` (`shrink = 1 − 0.035·cirrhosis`),
nodule cells `:604-612`, `app.css:500-501`. Raise the contour amplitude to ~6 units at full cirrhosis
with irregular wavelengths (14–40) so the inferior edge scallops; scale to 0.92 and raise the right-lobe
atrophy term from 0.15 to ~0.24 so the liver pulls away from the flank and ascites shows around it;
morph the intrahepatic node positions (`LIVER_INNER`, `anatomy.js:508`) through `liverField` so vessel
tips stay inside the shrinking organ; give nodules a per-cell radial fill (lighter centre, darker under
the septum) and mix macro- and micronodule populations by severity; drop septa opacity to ~0.32; keep
~40 % of the capsule gloss (`:616-618`, currently faded 75 %).

**G2. Dark-mode organs: re-light, do not darken (S).** `styles/tokens.css:236-246` (and the duplicate
block 283–293): the lit-face tokens are 20–30 % lighter than the ground and desaturated, the rim light
is 0.14 white. Raise each `--og-*-1` by ~12 L* and keep `-2` dark so every organ has a lit top-left and a
dark lower-right (liver #A06A62→#5A3440, spleen #8A6694→#483456, stomach #9C6E74→#573846); set
`--og-light` to rgba(255,235,225,.3) and `--og-ao` to rgba(0,0,0,.45); tokenise `#ogVol`'s highlight
stop (`stage.js:551`, fixed 0.22) with a dark-theme value of 0.3; raise `--diaphragm` opacity in dark
from .7 to .85. Check the vessel casing (`--casing-rgb`) against the lighter organs.

**G3. Lit forms, not a diagonal tint (M).** `#ogVol` (`stage.js:551`) puts the same highlight at
(0.34, 0.26) of every organ's box; `.org-shade.s1–s3` (`app.css:2643-2645`) is a uniform ring. Per-organ
highlight centres declared in `ORGANS` (`lit: [x, y]`), a broad second gradient stop at 0.62 so the turn to
shadow starts earlier, a true cast shadow where the liver overlaps the stomach and colon (the unused
`#castShadow` filter at `stage.js:436`, applied once at raster time), and `.org-ao` doubled.

**G4. Splenomegaly that grows the right way (S).** `stage.js:3817-3819` scales isotropically about
`SPLEEN_CENTER`; a real spleen grows inferomedially toward the umbilicus. Anchor at the upper-lateral
pole, scale anisotropically (`sy = sc`, `sx = 0.6 + 0.4·sc`), deepen the fill toward `--og-spleen-2` and add
`texFine` mottle at `0.1·(sc−1)` for congestion; draw two or three hilar notches. Keep the splenic-vein tip
(`TIP_FADE.V_SPL`, `anatomy.js:235`) at the hilum.

**G5. Draw the pancreas and a gallbladder (S).** Tokens (`--og-panc-*`, `--og-gb`), the `#texLobules`
pattern (`stage.js:439`) and `.organ-pancreas` CSS (`app.css:471`) all exist; `ORGANS` never draws them, so
the splenic vein floats in empty space. A faint lobulated band from the duodenal C-loop to the splenic
hilum, in the mid tier so the vein runs behind it; a small gallbladder under the right lobe gives the
liver its fossa.

**G6. Ascites that surrounds organs (M).** `veins-gl.js:978-993` (fluid in the composite shader),
`stage.js:3833-3925`. Depth shading (`a = a0 · (0.35 + 0.65·smoothstep(0, 120, d))`), a thin brighter
band at organ edges inside the fluid (sample the organ-cover texture already bound in the vessel pass),
and let the small-bowel group drift up by `bulge·6` units (the comment at `:3834` promises the bowel
floats, nothing moves it).

**G7. Caput medusae needs its umbilicus (S).** `anatomy.js:435` draws the umbilicus at opacity 0

### Vessels

**G13. Wall thickness and distension (M).** The casing is a fixed ~1 px line (`stage.js:2204`,

texture the GPU already supports (`veins-gl.js:87`); shorten the wiggle wavelength as pressure rises.
Match the endoscopy's `beaded = grow > 0.5` (`src/ui/endo-render.js:102`).

**G15. Sinusoid "fish-net bulbs" → a parenchymal fade (S).** `STRANDS.SIN_RR/LL` (`anatomy.js:217-218`)

trunk, and add a soft radial perfusion glow behind them (reuse the congestion glow path,
`veins-gl.js:305-313`, pressure colour at 0.18 alpha, reach 30) so blood appears to sink into tissue.

**G16. A hair of volume on wide tubes; 3× on phones (S).** `veins-gl.js:492-507` draws two hairlines that
vanish at reference size. Add a broad faint lateral gradient (dark side 0.10, light side 0.06) only when

`quality === 0` and the canvas is under ~3 Mpx; a 390×844 phone at 3× is 3.0 Mpx and the compositor is one

## 7. Implementation plan

Each phase is one `claude/<name>-preview` branch merged to the integration branch for device testing,
following AGENTS.md (lint + unit tests + screenshots before each push; full `npm run check` before merge;
run `visual-refs.yml` after any intended look change). Phases are ordered so that the safety fixes and
the measurement tooling land before the visual work, and the visual work lands before the big refactor
(a refactor first would make every visual diff harder to review).

### Phase 0: safety and measurement (1–2 days)

1. Q1 engine crash toast and recovery, Q3 popover race, Q2 share-link hardening, Q4/U26 unknown preset.
2. Q14 fix the dead perf condition, generate matrices, add `tips-doppler` to the sweep; Q13 restore the
   deck cache; Q16 `pretest` stamp check.
3. Add `tests/e2e/frame-cost.mjs`: with the Tests dock open, hovering a vessel, and in the lobule, read
   `window.pps.perf().totals.ms` per surface over 10 s and assert budgets. This is the gauge for Phase 1.

Tests to add: singular-topology engine test; sanitize tests for `__proto__`, `view`, `cam`; a popover
open/close/open smoke.

### Phase 1: performance (2–3 days)

P1 chart glide, P2 home-framing and blocker reads, P4 layout reads in loops, P7 composite allocations,
P8 comparison header, P3 pressure-time scans, P5 credit signature, then P6 glow rows and P9 FibroScan
ripples. P10 (high-speed timestep) and P11 (lobule idle slices) last, each behind its own commit so the
owner can feel the difference on the phone.

Verify: `npm run perf -- --budget` on a machine with a GPU (the owner's laptop, or CI once Q14 lands),
`tests/e2e/idle-steady.mjs`, `npm run smoke:rows`, and the new frame-cost check.

### Phase 2: organs and dark mode (3–4 days)

G2 dark-mode tokens and G20 selection tone first (token-only, low risk), then G3 lit forms and cast
shadow, G1 the cirrhotic liver, G4 splenomegaly, G5 pancreas and gallbladder, G7 caput, G6 ascites.
